# Evidence for Reviewer A3SE03

## Scope

The LLM contributes runtime language-conditioned adaptation: it interprets a natural-language objective and instantiates a state-specific preference within the feasible action set. StateBuilder supplies scheduling features, the router supplies a safe strategy scaffold, and the Enforcer guarantees feasibility. JSON is deliberately used as a simple, model-friendly, machine-parseable serialization format; it is shared by the execution interface and is not treated as the source of the performance gain.

## Matched no-LLM control

The matched controller retains StateBuilder, router context, feasible actions, event stream, and Enforcer, replacing the LLM with deterministic implementations of the same template rules. It is intentionally strong when the tested objective has already been manually encoded. Its limitation is that the rule catalogue is closed: it cannot interpret a free-form objective, paraphrase, or new objective composition without adding a parser, score, or switching rule.

Across all 26 pairs, AGA-Sched versus no-LLM is -0.15% MK (95% CI [-4.26, 2.57], p=.9887) and +5.09% TD (95% CI [-14.45, 24.72], p=.6302); neither difference is significant. This shows that AGA-Sched adds language responsiveness without a significant average fixed-objective quality penalty. It does not imply that the no-LLM controller can adapt to a new linguistic objective.

The contrast isolates adaptation cost: prompt-only for AGA-Sched versus executable policy recoding for Urgent-CPL.
